This file combines the actual teardown-lab2.sh run with the manual S3
cleanup that followed, since the script's own bucket-emptying step (1/7)
had a bug and silently left 72 object versions in place, causing the first
terraform destroy to fail with BucketNotEmpty. Nothing below is simulated —
every step is the real output from this session.

At this point every resource Terraform owned except the S3 bucket itself
was destroyed (confirmed below by `terraform show` returning an empty
state for everything except the bucket). The script's own checklist above
doesn't check for a leftover bucket, so it reported "complete" prematurely.

---- Manual diagnosis and fix ----

$ aws s3api head-bucket --bucket northstar-dev-data-761641207876
{
    "BucketArn": "arn:aws:s3:::northstar-dev-data-761641207876",
    "BucketRegion": "us-east-1",
    "AccessPointAlias": false
}
(bucket still existed)

$ terraform -chdir=infrastructure/environments/dev show
# module.storage.aws_s3_bucket.data:
resource "aws_s3_bucket" "data" { ... }
(only the S3 bucket remained in state — everything else had been destroyed
cleanly by the run above)

$ aws s3api list-object-versions --bucket northstar-dev-data-761641207876 --query 'length(Versions)' --output text
72
(72 object versions confirmed present — raw/customers/, processed/customers/,
features/customers/, and the Feature Store offline store's own files)

$ aws s3api list-object-versions --bucket northstar-dev-data-761641207876 --max-keys 1000 --output json --query '{Objects: Versions[].{Key:Key,VersionId:VersionId}}' > del_versions.json
$ aws s3api delete-objects --bucket northstar-dev-data-761641207876 --delete file://del_versions.json
{
    "Deleted": [ ... 72 objects ... ]
}
(all 72 versions deleted in one batch call)

$ aws s3api list-object-versions --bucket northstar-dev-data-761641207876 --query 'length(Versions)' --output text
(empty response — zero versions and zero delete markers remained)
